## Context

当前首页（`src/pages/index.astro`）包含三个主要区域：
1. Hero 区域（个人品牌 + 技能标签）
2. 精选文章区域（`featuredPost`，大卡片展示）
3. 最新文章列表（`recentPosts`，4 篇文章的网格）

数据层通过 `getCollection("blog")` 获取所有文章并按日期排序。Tailwind CSS 用于样式，已有响应式断点和水墨风格主题系统。

## Goals / Non-Goals

**Goals:**
- 移除首页中所有文章相关的渲染逻辑和数据获取
- 重构首页为以个人品牌为核心的现代主页布局
- 保持现有的水墨风格主题系统和响应式能力
- 保持页面加载性能

**Non-Goals:**
- 不修改博客列表页（`/blog`）、文章详情页、关于页、工具页
- 不引入新的前端框架或运行时依赖
- 不修改内容集合 schema 或文章数据结构
- 不修改路由结构或部署配置

## Decisions

### 数据层简化
移除 `getCollection("blog")` 调用。首页不再需要动态获取文章数据。Hero 区域的文案和项目数据可内联在组件中，或从 `consts.ts` 读取常量。

### 组件策略
- 复用现有组件：`BaseHead`、`Header`、`Footer`
- 新增首页专用区块组件或直接在 `index.astro` 中内联实现（视复杂度而定）
- 保留 `FormattedDate` 供可能的项目时间线使用

### 布局结构
```
<main>
  <section id="hero">        ← 个人品牌、标语、主 CTA
  <section id="showcase">    ← 项目/作品展示（2-4 个卡片）
  <section id="nav-cards">   ← 博客、关于、工具等入口卡片
</main>
```

### Hero 区域设计
保持当前 Hero 的 `min-h-[32rem]` 高度和圆角卡片风格，移除技能标签区域，聚焦于个人名称、标语和单一 CTA 按钮。

### 项目展示区域
使用卡片网格布局（移动端单列，桌面端 2-3 列），每张卡片包含项目名称和描述。项目数据可内联或从常量文件读取。

### 导航卡片区域
使用 3 列水平排列（移动端堆叠），每张卡片对应一个主要页面入口（博客、关于、工具），带标题和简短说明。

## Risks / Trade-offs

- **内容硬编码**: Hero 和项目数据内联后，更新内容需要修改代码而非编辑 Markdown。对于个人站点可接受。
- **移除文章曝光**: 首页不再展示最新文章，可能降低博客内容的发现性。通过导航卡片引导用户前往 `/blog` 页面补偿。
